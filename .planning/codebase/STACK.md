# Technology Stack

**Analysis Date:** 2026-10-14

## Languages

**Primary:**
- Python 3.11+ and <3.13 - application services, agents, shared schemas, database access, parsers, scripts, and tests across `apps/`, `packages/wildfire_core/`, `scripts/`, and `tests/`.

**Secondary:**
- SQL - PostgreSQL schema and migration statements in `infra/migrations/versions/` and initialization in `infra/postgres/init.sql`.
- YAML - application defaults in `config/defaults.yaml`, Docker Compose in `docker-compose.yml`, and Python project configuration in `pyproject.toml`.
- Dockerfile - container definitions in `infra/docker/api/Dockerfile` and `infra/docker/postgres/Dockerfile`.

## Runtime

**Environment:**
- CPython 3.11 or 3.12, constrained by the root and workspace package manifests; the API container uses Python 3.12 slim (`pyproject.toml`, `apps/*/pyproject.toml`, `packages/wildfire_core/pyproject.toml`, `infra/docker/api/Dockerfile`).
- Docker Compose provides local PostgreSQL, Redis, and API services (`docker-compose.yml`).

**Package Manager:**
- `uv` workspace, pinned in CI to 0.8.17 (`pyproject.toml`, `uv.lock`, `.github/workflows/ci.yml`).
- `uv.lock` is present and CI installs with `uv sync --locked`; `requirements.txt` is an autogenerated export. The API image installs the local core and gateway packages with `pip` (`requirements.txt`, `infra/docker/api/Dockerfile`).

## Frameworks

**Core:**
- FastAPI 0.142.2 - the API gateway and health/config endpoints (`apps/api_gateway/pyproject.toml`, `apps/api_gateway/src/api_gateway/main.py`).
- SQLAlchemy 2.0.54 and Alembic 1.20.0 - PostgreSQL engine, table access, and schema migrations (`packages/wildfire_core/pyproject.toml`, `infra/migrations/`).
- Pydantic 2.13.5 and pydantic-settings 2.15.0 - domain/configuration validation (`packages/wildfire_core/pyproject.toml`, `packages/wildfire_core/src/wildfire_core/config.py`).
- Uvicorn 0.35.0 - ASGI server (`pyproject.toml`, `infra/docker/api/Dockerfile`).

**Testing:**
- pytest 8.4.2 and Hypothesis 6.168.3 - unit, integration, and property-based test dependencies (`pyproject.toml`, `tests/`, `packages/wildfire_core/tests/`).

**Build/Dev:**
- Hatchling 1.27.0 - builds the `api-gateway` and `wildfire-core` workspace packages (`apps/api_gateway/pyproject.toml`, `packages/wildfire_core/pyproject.toml`).
- Ruff 0.16.9 - linting/import ordering; mypy 2.3.1 - strict type checking (`pyproject.toml`, `.github/workflows/ci.yml`).
- CI runs `uv sync --locked`, Ruff, mypy on `packages/wildfire_core`, unit tests, and a Docker Compose migration/integration smoke job (`.github/workflows/ci.yml`).

## Key Dependencies

**Critical:**
- `wildfire-core` - workspace package shared by the gateway, ingest worker, and agents (`pyproject.toml`, `packages/wildfire_core/pyproject.toml`).
- `psycopg[binary]` 3.3.6 - PostgreSQL driver (`packages/wildfire_core/pyproject.toml`).
- `redis` 8.1.0 - Redis client for readiness checks and the Redis publish adapter (`packages/wildfire_core/pyproject.toml`, `packages/wildfire_core/src/wildfire_core/events.py`).
- `httpx` 0.28.1 - declared at the root and API gateway; no active external HTTP client call sites are present in application code (`pyproject.toml`, `apps/api_gateway/pyproject.toml`).

**Geospatial and Modeling:**
- `shapely` 2.1.2, `pyproj` >=3.6.0, `scipy` >=1.12.0, `scikit-learn` >=1.4.0, and NumPy >=2.0.0 - geometry, projection, numerical, clustering, and fire-model code (`pyproject.toml`, `apps/agents/fire/pyproject.toml`, `apps/ingest_worker/pyproject.toml`).
- `PyYAML` 6.0.3 - reads application defaults (`packages/wildfire_core/src/wildfire_core/config.py`).
- PostgreSQL extensions PostGIS, pgvector, and pgcrypto - installed by `infra/postgres/init.sql` and migrations; the custom PostgreSQL image builds pgvector 0.8.6 (`infra/docker/postgres/Dockerfile`, `infra/migrations/versions/0001_extensions_and_aoi.py`).

## Configuration

**Environment:**
- Defaults are read from `config/defaults.yaml`; `load_settings()` overlays recognized environment variables and validates them with Pydantic (`packages/wildfire_core/src/wildfire_core/config.py`).
- `.env.example` lists the local development configuration surface. `.env` is present; its contents were not read.
- Settings include `APP_ENV`, `LOG_LEVEL`, `AOI_NAME`, `AOI_BBOX`, `PILOT_CLUSTER_ID`, `WEATHER_PROVIDER`, `FIRMS_SOURCES`, `LLM_ENABLED`, `LLM_PROVIDER`, `LLM_MODEL`, `DATABASE_URL`, `REDIS_URL`, `POSTGRES_PASSWORD`, `GROQ_API_KEY`, and `OSM_CACHE_PATH` (`packages/wildfire_core/src/wildfire_core/config.py`).
- Compose additionally interpolates `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`, `REDIS_PORT`, and `API_GATEWAY_PORT` (`docker-compose.yml`). Sensitive URLs/passwords/API keys use Pydantic `SecretStr` where represented in application settings (`packages/wildfire_core/src/wildfire_core/config.py`).

**Build:**
- Workspace membership and shared source configuration are defined in `pyproject.toml`; individual installable packages are in `apps/*/pyproject.toml` and `packages/wildfire_core/pyproject.toml`.
- Migration configuration is in `infra/migrations/alembic.ini`; compose and container build configuration are in `docker-compose.yml` and `infra/docker/`.

## Platform Requirements

**Development:**
- Python 3.11 or 3.12, `uv`, and Docker Compose for database/cache-backed integration tests (`pyproject.toml`, `.github/workflows/ci.yml`).
- The workspace uses compiled/geospatial dependencies, including NumPy, SciPy, Shapely, pyproj, and scikit-learn (`pyproject.toml`).

**Production:**
- No production hosting target or production deployment manifest is defined. The checked-in deployment is a local/CI Docker Compose stack containing PostgreSQL, Redis, and the API; it does not define ingest-worker or agent services (`docker-compose.yml`).
- Container images are pinned by digest for the API base and Redis, and the PostgreSQL image is based on PostGIS for PostgreSQL 16 / PostGIS 3.5 (`infra/docker/api/Dockerfile`, `infra/docker/postgres/Dockerfile`, `docker-compose.yml`).
