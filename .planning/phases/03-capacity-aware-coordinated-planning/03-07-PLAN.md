<objective>
Build the stage that turns a `PlanDraft` into an immutable `IntegratedPlan`. That covers finalization with the S5 gate (failed versus pending_review), strict V8 rationale grounding with template replacement (D-13), freshness and provenance builders (PLAN-08), and the two bounded LLM entry points. The first is an enum-only fix-menu chooser using Groq strict structured output (D-09, D-10). The second is a compact plan-rationale call.

Purpose: The LLM may only pick from a fixed menu and write grounded text (S4). Invalid plans can never reach review (S5). Every plan carries provenance and freshness.
Output: `planning/finalize.py`, `planning/grounding.py`, `planning/rationale_template.py`, the `groq_adapter.py` additions, versioned prompt files, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| coordinator → Groq API | Plan summaries and violation counts leave the process |
| LLM output → control flow / rationale | Untrusted model text and choices re-enter the plan |
| draft → reviewer | finalize decides what can reach pending_review |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07-01 | Tampering | LLM invents a shelter, number or id in a rationale (S4) | high | mitigate | Strict V8 grounding of numbers, uuids and registry names, with template replacement and the reason recorded (D-13). Property: template always grounded. |
| T-03-07-02 | Tampering | LLM steers control flow outside the menu or names targets | high | mitigate | Strict json_schema enum, Pydantic validation, membership check, one repair retry then deterministic fallback. Targets are chosen deterministically. |
| T-03-07-03 | Elevation of privilege | An invalid plan reaches pending_review | high | mitigate | finalize forces failed on any fail status. The IntegratedPlan validator rejects pending_review with failures (plan 03-02). |
| T-03-07-04 | Information disclosure | Data egress to Groq | medium | mitigate | Settlement-level data only. Compact summary with no coordinates or paths. The fix-menu payload is code counts only, with id/name keys rejected. Gated by llm_enabled and key. |
| T-03-07-05 | Tampering | Prompt injection through shelter or settlement names in data | medium | mitigate | Names are only data inside JSON. The model's output is constrained to an enum for control flow, and free text is V8-checked. Rules 12.10. |
| T-03-07-06 | Denial of service | LLM latency or quota | low | mitigate | Gate before any client, request timeout, token caps, and deterministic fallback on any error |
</threat_model>
